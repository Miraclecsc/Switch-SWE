For example, the more explicitly one uses a backend, then the more hard we should try to use that backend. Thus, we have: 1. If `backend=backend_name` is given then use that backend (and fail if can't) 2. If you pass in a backend graph to an algorithm, then _try_ to use that backend 3. Putting `"networkx"` in `backend_priority` would make it "sticky", which we don't want. `backend_fallback`, as the name implies, is intended for _falling back_. We will try to convert and use these backends _after_ trying to use higher priority backends (backend from inputs, and backends in `backend_priority`). Backends in `backend_fallback` _are not_ "sticky", so they will be attempted to be converted to use backends listed in `backend_priority` if possible.
