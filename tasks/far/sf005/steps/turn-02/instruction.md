One more thing: Extend the same async receiver context sharing to reentrant dispatch. When an asynchronous receiver awaits another Signal.asend() or Signal.asend_robust(), that nested dispatch is part of the same live context as its enclosing dispatch, including concurrently running sibling async receivers. A value set by an outer sibling while an inner receiver is suspended must be visible when the inner receiver resumes; a value set by that inner receiver must be visible to an outer sibling before the nested dispatch returns. Do not restore an obsolete inner snapshot over a sibling's changes.
Keep receiver response ordering and exception behavior: robust dispatch returns the exception for that receiver while preserving context writes; a single nonrobust receiver exception remains that exception, and the top-level caller still receives context updates on completion or error.
Sharing is scoped to a dispatch invocation and its awaited nested dispatches. Independent top-level dispatches started by separate caller tasks keep their contexts isolated. After a top-level dispatch completes, a later dispatch must start from the caller's current values, not a retained prior snapshot. Preserve sync receiver behavior and all original tests. Do not serialize async receivers to avoid the sharing requirement, and do not add a global mutable context shared by independent callers. No particular private helper or context representation is required.
