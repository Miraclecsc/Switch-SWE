And here, I would prefer a different approach to task-level KI protection. This one adds function call overhead to every task step, as well as a traceback frame for every level in the task tree. Here's an alternative idea: use a contextvar to indicate task-level KI protection, and have `_run` tell the KIManager which code object corresponds to `unrolled_run`. If stack unwinding reaches that object, KI protection should be based on the contextvar. `Context.run` is written in C, so as long as the contextvar is set to enable KI protection when outside of any task, this approach should be just as safe as the one you're using.
