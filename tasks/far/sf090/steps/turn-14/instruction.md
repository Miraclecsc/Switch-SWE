One more thing: The reason to use a contextvar is that we are already atomically switching contexts when we enter and exit the task. If you use a thread-local, then you have a brief period where the task is not running but the KI protection is still as if the task were running. This must be managed carefully in order to avoid an unprotected KI being raised directly inside `unrolled_run`. The contextvar solution is more obviously correct IMO.
