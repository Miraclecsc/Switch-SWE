So far I've received just two alternative proposals: 1. Have the formerly-async functions return dummy awaitables. This falls apart when the functions return meaningful results, such as `current_time()` or `MemoryObjectStream.receive_nowait()`. It would end up some code working properly while other code would not. 1. Keep the async functions but add synchronous alternatives. While this would retain full backwards compatibility, it not only clutters the API significantly, but will also not achieve the second goal of this effort: to get closer to the trio API.
