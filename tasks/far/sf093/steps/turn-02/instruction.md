One more thing: Could you also check that something already blocking will also not borrow the capacity limiter? For instance, you start 6 `c.acquire_on_behalf_of` so there's 1 waiting for a release to acquire a token -- if you have `c.total_tokens == 0` before releasing anything, in theory there should be a single task trying to borrow things... but unable to. (tbh that's probably already tested earlier, though)

Add CapacityLimiter.pause(), a synchronous context manager that temporarily prevents all new acquisitions without revoking existing borrowers or changing configured total_tokens. While paused, available_tokens is zero, nowait acquisition raises WouldBlock (while retaining the existing duplicate-borrower error), and async acquisition waits normally. Releasing a borrowed token while paused must not wake a new borrower. Exiting pause restores acquisition using the configured capacity.
