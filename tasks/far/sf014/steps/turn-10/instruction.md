One more thing: For a query on a multi-attribute GSI, validate a supplied ExclusiveStartKey as a complete typed cursor before comparing or sorting it. It must contain exactly the union of that index's HASH/RANGE attributes and the base table's primary-key attributes, each with the declared scalar key type. Missing attributes, extra non-key attributes and wrong AttributeValue types raise ValidationException.
The cursor's GSI HASH values must equal the query's HASH conditions using that type typed equality; reject a cursor for another partition. Do not require the original start item to still exist: a complete cursor must resume by key order after deletion. Numerically equivalent cursor values remain equivalent, the caller's cursor must not be mutated, and descending pagination must visit each remaining matching key once.
Preserve original composite key ordering, range predicates, sparse-index exclusion, projections, both query input APIs and all original tests. This extends the existing pagination mechanism rather than changing the task's key schema or adding opaque token state.
