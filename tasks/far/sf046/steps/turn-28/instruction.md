I assume you already reviewed if LLMs were indeed used. ## Algorithm: clarify relationship to the paper The docstring and Notes say this implements "BFC-VP from Wang et al. [2]", but that's not quite accurate. The paper's Algorithm 2 (BFC-VP) computes only a **global** butterfly count (a single integer X_G). It uses a simple `wedge_cnt` dict per start node and accumulates C(k,2) into a running total. The paper's Theorem 4 proves O(m) space precisely because it only stores this integer-valued dict. The PR extends BFC-VP with **per-node attribution**; distributing butterfly credits to start, end, and middle nodes. This extension requires the `wedge_mid` data structure (a list of middle nodes per end node), which is not in the paper and is the reason the O(m) space claim doesn't hold. I've verified it gives correct results against brute-force enumeration on several graphs, but the docstring should be honest about what comes from the paper (the priority-based wedge enumeration) and what is a custom extension (the per-node attribution). ## Refactoring `_four_cycles` The priority-based wedge enumeration from BFC-VP is an improvement over what we currently have in `_four_cycles()`. Since `_four_cycles` is a private helper with a single call place in `robins_alexander_clustering`, I think we should remove it entirely and use `butterflies()` directly: This removes 17 lines of slower duplicate counting logic and makes the relationship between the two functions explicit. Note that `butterflies()` includes a bipartite check that `_four_cycles` lacks. This is actually an improvement since BFC-VP requires bipartite structure and `robins_alexander_clustering` currently silently gives wrong results on non-bipartite graphs. The O(n+m) cost of the check is negligible compared to the counting itself. ## Docstring The definition, parameters, examples, and cross-references are good.
