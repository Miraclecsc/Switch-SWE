In the checkout at /work/w01, BUGFIX: spring energy and ARF layouts with zero iterations This one is almost certainly a corner case bug In a spring layout with specified initial coordinates, `scale=None`, and `iterations=0`, one would expect that the algorithm returns exactly the input coordinates. Instead, the energy layout function passes the entire shebang to `scipy.optimize.minimize` which, despite the number of requested iterations being zero, returns a different array. Example: This does return the correct values if `method="force"`, which uses a different code path. This PR fixes the bug with a two-liner and also adds a test for both "force" (which verifies it already works) and "energy" (which underpins this bug).
