And here, After merging #8235, the last test here was obviously failing because of an invalid degree sequence. I decided to dig in to see if the check for "one too many" was still necessary. Outside of the trivial `deg_seq == [0]` case (that I felt was more idiomatically handled by adding an explicit check), I convinced myself that it wouldn't be by considering the following two extreme cases: a path graph with the minimum number of degree-one nodes (2), and a star graph with the maximum number of degree-one nodes (length - 1). Both of these cases return the correct number of nodes (I also added tests for this). I additionally verified this intuition by writing a quick generator of (valid) degree sequences: and trying to run `nx.degree_sequence_tree` on >10000 randomly generated sequences, to see if one of them would hit the "one too many" branch. None of them did.
