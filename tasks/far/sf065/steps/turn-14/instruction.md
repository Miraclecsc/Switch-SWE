One more thing: The API for Leiden is very similar to Louvain, but I did remove `threshold=` parameter that is in Louvain and was included in #5964. I don't think threshold makes as much sense for Leiden, and implementations I've seen typically don't include it. Louvain uses a greedy optimization method, so using a threshold can make sense here to stop considering updates when they only marginally improve modularity. Leiden, on the other hand, includes an additional refinement step that help ensure the communities are well-connected and meaningful. Hence, I think refinement in Leiden makes the threshold parameter unnecessary. Both have the `resolution` parameter that already control the granularity of the communities. In other words, Leiden is already well-behaved and well-parametrized without needing `threshold`, which would be redundant and unnecessary. That's my understanding anyway. So, I think this is ready to go in pending review of the docstring and general approval of adding a backend-only algorithm (which there seems to be).
