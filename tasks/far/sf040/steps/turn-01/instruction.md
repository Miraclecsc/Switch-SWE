I have this in /work/w02: fix: permit s3 sns raw delivery without message attributes ## Summary This fixes an S3 notification bug in Moto when a bucket notification targets SNS and the SNS subscription to SQS uses `RawMessageDelivery=true`. Moto's S3 notification path publishes to SNS without message attributes. In the raw SQS subscription delivery path, Moto assumed `message_attributes` was always present and iterated `message_attributes.items()`. When S3-originated publishes passed no attributes, that raised an exception and the notification was silently dropped by the S3 notifier's exception-swallowing path. This change guards the raw delivery path against missing message attributes and adds a regression test covering `S3 -> SNS -> SQS` raw delivery. ## Test plan - Added a regression test in `tests/test_s3/test_s3_lambda_integration.py` - Verified the new test fails against the pre-fix code - Verified the new test passes with the fix - Ran: ## Reproduction 1. Create an S3 bucket notification with a `TopicConfiguration` 2. Subscribe an SQS queue to that SNS topic with `RawMessageDelivery=true` 3. Upload an object to the bucket 4. Before this fix, the raw SQS subscription does not receive the S3 notification 5. After this fix, the raw SQS subscription receives the expected S3 event payload
