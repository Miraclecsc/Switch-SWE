And here, This is the proposed change I'm least sure about. One could argue that this should raise that type exception here, as it is indeed pointless to try to generate trees with 0 nodes. After much thought, I decided this was the better pattern. For one, it's more consistent with `nx.number_of_nonisomorphic_trees`. More importantly (IMO) this also prevents exceptions from breaking execution flow in cases where 0's might show up. For example, consider the following use case: Raising for `order=0` would require uses to wrap `do_something` in a try/except. The way it's currently implemented, the `order=0` case simply becomes a no-op; no try/except required!
