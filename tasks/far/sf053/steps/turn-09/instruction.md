Also, Extend MemoryObjectReceiveStream with async receive_many(max_items). Require a positive integer, rejecting bool/non-integers with TypeError and nonpositive values with ValueError before consuming anything. Wait for the first item using the ordinary receive cancellation/checkpoint contract, then return a FIFO list of at most max_items by draining only immediately available buffered items or waiting senders, without awaiting between extra items. Return a partial list on temporary emptiness or sender EOF after at least one item; if EOF occurs before the first item, raise EndOfStream. Closed receivers raise ClosedResourceError. Clones share the same queue. Cancellation before the first receive must not consume buffered data, and draining waiting senders must correctly unblock them.
