Return an opaque nonempty Marker iff more matching records remain; omit it when exhausted (including an empty result). Supplying a returned Marker resumes beyond its page. A token is reusable, page size may change, and concurrent traversals must not interfere.
For reproducible emulator behavior, v1 adds this explicit snapshot-membership policy: a traversal captures matching task incarnations in creation order at its first request. Later creations, including delete/recreate of the same identifier, are excluded; deleted pending tasks are skipped, filling the page from the remaining original members. Deleting previously returned tasks must not shift the continuation. An exhausted deleted tail returns an empty terminal page. New traversals see current tasks.
Tokens are scoped to the account, region and filter query that created them. Unknown/malformed tokens, tokens used in another account/region, or tokens used with a different filter query raise DMS ValidationError. Reordering filter clauses, reordering values and repeating a value do not change the query; omitted Filters and [] are the same query. Preserve existing handling of unsupported filter names. Tokens remain reusable for the lifetime of that backend; no expiration or persistence format is required.
