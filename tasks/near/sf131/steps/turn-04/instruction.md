In the checkout at /work/w00, Ignore malformed `Host` header when constructing `request.url` When the `Host` header contains characters invalid per RFC 9110 §7.2 (/,., #, @, \, spaces, etc.), `urlsplit` can produce a URL whose path differs from `scope["path"]`, making `request.url.path` unreliable. Validate the header against an allowlist regex (matching Werkzeug's and Django's approach) before using it. Fall back to the `server` tuple from scope when the header is malformed, same as when no `Host` header is present.
