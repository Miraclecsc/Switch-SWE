And here, > Would you mind inverting the logic and just make the Zope tests conditional on the presence of Zope.interface? That seems to be the more common approach nowadays anyways. Yeah, that's easy enough — the main difference between that approach and this one is that with this approach, it would be very hard to _accidentally_ disable the zope-related tests, whereas if you always disable the zope-related testing whenever `zope.interface` isn't present, anyone who fails to declare a test dependency on `zope.interface` will silently start skipping tests. I figured this is a niche enough thing to want that it's better to require enthusiastic opt-in, but maybe it's not that big a deal if these tests sometimes get accidentally disabled in downstream testers?
