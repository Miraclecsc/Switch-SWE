The full set of unit tests would not pass on my system; Unix socket tests were failing with `OSError: AF_UNIX path too long`. My new tests for `walk_up` are limited to `test_fileio.py`, but I thought it polite/good practice to make sure the test suite was "all green" in the PR. On macOS, the unix socket path length limit is 107 bytes; the base temp directory of `/private/var/folders` combined with the deep hierarchy of subdirectories pytest creates regularly exceeds this limit by 10+ bytes. Linux also has this limit (108 bytes), but because it's almost always rooted at `/tmp` or `/var/tmp` it's unlikely to trigger this error. These limits are discussed more here: python/cpython#93852 A simple workaround was to use `tempdir.TemporaryDirectory` for socket paths. Even on macOS, these paths are short enough that they shouldn't trigger this error, while still using standard tempdir conventions.
