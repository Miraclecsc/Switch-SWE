One more thing: Great question, Ross. I'm not personally married to the notion that classes shouldn't have methods, but I think the line should be "don't make a standalone function that must depend on the guts of a class." And in this case, `mark_half_edges` depends on the internals of the combinatorial embedding data structure that that type class maintains\*. I would be inclined to make this a method. \* specifically if we adopt a different representation of embeddings that can handle surfaces other than the plane, one might want to find facial walks and making such a class conform to the `mark_half_edges` interface might be a wart

Add optional half_edges=None to faces. A supplied one-shot iterable of directed half-edges selects the faces on those directed sides. Yield each selected face once, in order of first occurrence among the seeds. Reverse half-edges can select distinct faces; several seeds on one boundary must not duplicate it. None still enumerates all component-local boundaries, and an empty iterable selects none.
