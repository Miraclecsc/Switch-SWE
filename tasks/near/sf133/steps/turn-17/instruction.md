The algorithm is bog-standard and will appear (or be taken for granted) in any reference that mentions the algorithm implemented in `PlanarEmbedding.traverse_face` -- this is just the clean way to enumerate all the faces of an embedding. An easy (and by my eye, pretty good) list of references can be found here: > Is a list of sets a convenient data structure for the result? No, it should be a list of lists (perhaps lazier and less mutable; an iterable of tuples?) -- facial walks can visit nodes multiple times, and it's important to know what order that happens in.

Extend PlanarEmbedding.faces with keyword-only as_edges=False. When True, yield each facial boundary as a list of consecutive directed (u, v) half-edges, including the closing edge. Keep the default node lists. Bridges must occur in both directions and repeated vertices must retain all incidences.
