Please check this too: I don't think I've ever seen an import inside a class definition before - this is a clever way to work around the fact that we need to access something from inside `attr` but this code will be `eval`'d in a namespace we don't own and can't control. But, to avoid subclasses seeing this, it should probably be `del`'d after we're done defining `__hash__`. An alternative would be: That's one line instead of 3, and `__import__` is maybe a bit less weird than an import inside a class body - at least, I've seen it more.
