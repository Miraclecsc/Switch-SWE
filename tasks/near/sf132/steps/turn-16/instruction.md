The original logic is: graph G is passed as arg, rev(G) if its directed(line 112) then calculate distances of rev(G) internally using nx.single_source_shortest_path_length. This code does exactly that in a different order: User passes G and distance calculation sp of G (by calling all_pairs_shortest_path_length beforehand) as args, then the function reverses G. Since internally sp must be calculated for rev(G) we "invert" the sp internally. I'm not assuming strongly connected because line 137 only considers reachable nodes. This is what both nx.single_source_shortest_path_length and all_pairs_shortest_path_length do too.

Add keyword-only sp_orientation="outward". The default describes ordinary distances from the original graph, as before. sp_orientation="inward" means each row already contains distances into its row node (for example all_pairs_shortest_path_length(G.reverse())); directed closeness must use these rows directly instead of transposing them again. Both orientations must match an ordinary uncached calculation. For undirected graphs they are equivalent.
