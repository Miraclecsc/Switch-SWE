I have this in /work/w00: Fix BC scaling for source nodes with k and endpoints=False This is a follow up to #7908 and specifically @dschult's question from > The case with k < n and endpoints is False still confuses me. It seems like the number of valid (s, t) node pairs that could have a path through v where s != t should depend on whether node v was in the sample or not in the sample. The largest possible count for nodes in the sample (when endpoints is False) is (k-1)*(n-2), but for nodes not in the sample the count can be k*(n-2). Why are we using k*(n-2) for all the nodes? After investigating this, I think source nodes and non-source nodes do indeed need to scale differently when `k` is given and `endpoints=False`. I added a test that exercises this. I don't fully grok the test results, but I trust the scaling logic more than I did. CC @ChuckHastings @rlratzel
