There is another part of this that I was wrestling with over the weekend. Instead of adjusting the scaling factor based on whether a node is in the sample or not, could we replace `k` with the expected value of the number of paths? That is, each node has chance `k/n` of being in the sample, so instead of `k` and `k-1` for the different nodes, we could use `k - k/n`. That then is `k*(n-1)/n` which turns us around to scaling by `n/k` instead of `(n-1)/k`. This feels like it reverts some of the changes we made in the previous PR. But -- because we do have the set of nodes that are sampled, I prefer using that information for scaling. I guess I don't trust the "Law of large numbers " when we can use the more precise small numbers information. I was working on this, but got distracted by our `undirected graph` adjustment when sampling. I think there are troubles there too. Perhaps this is better for yet another PR though. When `k=1` we know that we have not double-counted any undirected paths. So we should NOT be dividing the count by 2. When `k=2` we know that we considered at most 1 double-counted path. In general, we consider `k(k-1)/2` paths twice, and the remaining `k*(n-2) - k(k-1)/2` paths once. There must be a way to adjust our scaling of the undirected case to account for this bias when sampling.
