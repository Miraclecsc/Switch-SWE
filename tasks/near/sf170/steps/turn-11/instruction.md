Please check this too: AIUI, the `__eq__` operator on sequences just checks the items in order. In practice then, the difference in the comparison itself can be thought of as "row-first" (the current implementation) vs. "column-first" (this PR). In other words, the values that are being compared in both cases are the same, it's only the order that they're compared that's different and therefore should give the same result. Now, the area where there *is* a difference is the sorting, i.e. sorting the combined properties vs. sorting them individually. Again I believe sorting is done sequentially for sequence types (i.e. compare the first items first, then if there is no difference move on to the second items, etc.). In the end I think this means that two objects that compare the same may end up in a different order (unstable sort), but since they compare the same this won't have an effect on the end result - since ultimately comparisons are always done by value rather than by identity. All that's to say - I don't think there's a material difference between comparing the sequences of properties vs. the properties individually? My mental model of any one of these steps (or their composition) could be completely off :upside_down_face:
