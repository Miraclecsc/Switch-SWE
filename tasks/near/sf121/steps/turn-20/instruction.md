And here, The general change proposed makes sense to me. However, getting the traceback neatly formatted doesn't look straightforward. I had a quick play using `outcome`. This has the advantage that the sync and async traceback have the same number of frames that need to be remove. So no need to use the count variable to know how many levels to strip. The `InteractiveConsole.showtraceback()` already strips one level of the traceback. So I tried copying that into the `TrioInteractiveConsole` subclass and modifying it to strip two levels. I think this works. One complication is the original logic checks to see if `sys.excepthook` has been set and if so, doesn't strip the traceback frame. However in any python prior to 3.12, Trio includes `exceptiongroup` which *does* override the default `sys.excepthook`. In the implementation below, I'm stripping the two stack frame even when delegating to `sys.excepthook`. That is a little different to the stdlib version, but perhaps is a pragmatic middle ground.
